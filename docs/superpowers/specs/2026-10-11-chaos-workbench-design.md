# PulsePay Chaos Workbench

The user requests the available chaos UI and requires it to belong to the existing stack. Chaos Toolkit's documented visual offering is proprietary Reliably (https://chaostoolkit.org/offering/); the lab must retain free/local Docker-only operation. Provide a local browser adapter to the already implemented native Toolkit CLI, not another experiment engine.

Workbench listens on localhost:8090, is linked from PulsePay, and starts through normal `make up` alongside Locust and observability in the same project/branch. Scenario cards show targets, bounded exposure and unavailable capabilities; preflight, explicit confirmed Run, Abort and Restore call only fixed existing CLI commands. History exposes real summaries, timeline, journals and integrity evidence. Missing evidence stays UNKNOWN. No arbitrary YAML, flags, URLs, targets or shell code is accepted.

An unprivileged, read-only, 384-MiB/0.5-CPU web service has access to the existing runner mailboxes/evidence and read-only workload/baseline data. Only the existing gateway retains the socket. Watchdog remains a separate service. Default `make up` enables the control infrastructure without starting an experiment. Main Compose defines the UI and gated control infrastructure; the experiment overlay retains one-shot jobs. Base startup can show the UI with controls unavailable when the chaos profile is deliberately omitted.

State-changing browser requests require an allowlisted Host, matching Origin, JSON content type, session cookie and CSRF header. Inputs are strictly allowlisted. One browser action may execute at a time, except independent abort; the existing cross-process exclusive lease is still authoritative. Browser disappearance does not extend native fault TTL. Web shutdown stops its CLI child, leaving the independent watchdog to restore. Read APIs never launch faults. Evidence/job output is bounded and served through fixed names.

Locust manual sessions publish actual phase/user/request/commit/error snapshots using the same existing workload evidence contract. This supports preflight and productive post-restore checks without turning manual sessions into qualified performance baselines. No automated traffic starts at boot. CPU stress remains disabled; database interruptions retain their explicit environment opt-in. Proxy scenarios show their deliberate routing requirement rather than silently changing connections.

Acceptance: Docker unit/security tests, normal-stack startup with idle UIs, real Chromium access/history/no-fault preflight denial, then one explicit browser worker-pause under manual Locust traffic with genuine impact/restoration and read-only financial PASS. Preserve earlier seals/results. Same branch, no commits/pushes/new worktree. User task authorization supersedes redundant design-approval pauses and the earlier no-custom-dashboard restriction; native engine/safety boundaries are retained.
